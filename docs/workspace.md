# 桌面工作区设计（首版）

## 页面结构

- 顶部主导航保留工作区、轨迹、调用列表、仪表盘和设置。后四项沿用原有代理记录功能。
- 工作区左侧按项目显示 OpenCode 对话；右侧显示对话、文件改动和活动。这里的“活动”是当前 OpenCode 对话的工具步骤，顶部“轨迹”是代理录制的模型调用轨迹。
- 项目目录继续保存在现有的 `terminal-projects.json`，这样旧版保存的项目会直接出现在新工作区。对话及消息由 OpenCode 自己持久化，本应用只记住本次页面访问选中的项目和对话。

## 进程与数据流

```text
Tauri 窗口 / Web 页面
        │
        ▼
FastAPI 工作区 API ──► WorkspaceManager ──► opencode serve（每个项目一个本地进程）
        │                                           │
        │                                           └─► 现有 LLM 代理 ──► 调用记录 / 轨迹
        └─► 原有仪表盘、调用列表、轨迹、设置 API
```

OpenCode 服务只监听 `127.0.0.1`，使用每次启动随机生成的 HTTP Basic 密码。页面通过同源的 FastAPI API 获取会话、消息、文件差异和权限请求；SSE 与定时刷新用于更新进行中的对话。应用关闭或影响 OpenCode 的设置变化时，关闭由工作区启动的服务进程。

## 当前范围

已实现项目添加、历史对话读取、新建对话、文字消息发送、按 Provider 分组并搜索 OpenCode 模型、Agent 选择、项目斜杠命令与 shell 命令、回复与工具内容显示、文件改动摘要、权限确认、交互式提问和会话状态读取。可以给 OpenCode Provider 保存 API Key。对话列表显示完整的最后更新时间；OpenCode 返回的认证与请求错误直接出现在消息中，支持切换模型和填回提问。OpenCode 终端路由仍可通过 `#/terminal` 访问，但不是新工作区入口。

后续迭代可加入消息附件、完整代码差异、对话重命名和归档、面向大项目的服务进程空闲回收，以及更丰富的 Markdown / 工具结果展示。
